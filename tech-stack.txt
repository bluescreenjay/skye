AI Browser — Tech Stack & Feature Split
=======================================
Derived from initialspec.txt for constitution + Spec Kit feature planning.
Last updated: 2026-09-19 (prize stack preferred; originals are pivots)

PRODUCT CONSTRAINTS (from spec)
-------------------------------
- MVP: Chrome extension (Home + Side Panel) + server (NOT a full browser)
- Home: directory of all workspaces (Chrome new-tab / extension home)
- Sidebar: in-tab workspace in Chrome Side Panel when a web page is open
- Server: workspace state, AI context, plans, conversations, actions
- Core loop: Tab → Context → Workspace → Plan → Actions
- P1: desktop voice (ElevenLabs); saved workspaces
- Stretch: mobile companion, MCP, dynamic action discovery
- Long-term: optional Chromium-based browser

PIVOT RULE
----------
Prize vendors MUST NOT block the core loop. If Gemini, Tiger, ElevenLabs,
Vultr, or GoDaddy fails (signup, quota, API, time), switch to the pivot in
the same row and keep shipping. Document the swap in that feature plan.
Do not dual-run preferred + pivot as two sources of truth.

TIGER DATA — honest use (not a bolted-on dashboard)
---------------------------------------------------
Tab ingestion is a high-frequency event stream. Store it as a hypertable:

  tab_events (time, user_id, chrome_tab_id, url, title, workspace_id, event_type)

Use continuous aggregates for:
- time spent per workspace
- "what was I working on yesterday?"
- activity heat for clustering hints

Relational workspace/user tables live in the same Postgres.
Do NOT add MongoDB or a second primary database.
If Tiger is unavailable: same schema on Supabase Postgres; tab_events is an
ordinary table; "yesterday" queries use SQL or app-side aggregation.

DELIBERATE NON-CHOICES (week 1)
-------------------------------
- Full Chromium fork
- Computer-use / mouse-control agents
- Vector search as a hard dependency
- Native mobile (voice does NOT require mobile)
- Dynamic action discovery as required
- Solana (no honest product surface)
- Presage (camera vitals fight tab-privacy thesis)
- MongoDB Atlas (would duplicate Tiger/Postgres)
- Dual primary databases (don't run Tiger and Supabase at once)
- Treating prize vendors as un-pivotable (Gemini/Tiger/ElevenLabs/Vultr/GoDaddy
  are preferred; Claude/GPT, Supabase, skip-voice, Vercel are the originals)

CONSTITUTION PRINCIPLES (locked)
--------------------------------
1. Workspace-first — Unit of product is the workspace, not the tab.
   Tabs are inputs; workspaces own memory, plan, chat, and actions.
2. Extension observes and presents; server decides — Extension captures
   tabs, applies moves, and hosts Home + Sidebar; server owns clustering,
   persistence, and AI.
3. User corrections win — Manual drag/rename/merge/Other always overrides
   AI; corrections are learning signals.
4. Least-power actions — Prefer simple tools/APIs over agents; no
   computer-use in MVP.
5. One TypeScript surface — Shared types for Workspace/Tab/Plan/Message;
   no parallel models across clients.
6. Demo-hard, architecture-soft — Ship the core loop before polish.
7. Two surfaces — Home = all workspaces; Sidebar = in-tab workspace.

FEATURE SPLIT (SpecKit-sized, dependency order)
-----------------------------------------------
001  Monorepo + shared domain model
     Types; Tiger schema (users, workspaces, tab_events hypertable)

002  Tab ingestion extension
     MV3: list tabs, title/URL/snippet, change events, push to API

003  Workspace persistence API
     CRUD workspaces/tabs; user-scoped; "Other" bucket

004  AI clustering (Gemini)
     Cluster open tabs → named workspaces; low confidence → suggest

005  Home — all workspaces
     Chrome new-tab directory; Other bucket; workspace overviews

006  Chrome sidebar — in-tab workspace
     Side Panel on the current tab: workspace, related tabs, shells

007  Manual correction
     Home: drag across workspaces; Sidebar: move this tab; sync to Chrome

008  Workspace AI chat (Gemini, sidebar)
     Per-workspace context from tabs/snippets; Q&A without re-explaining

009  (cut) Plan generation
     Folded into 010: the checklist is one agent's output, saved as plan items

010  Workspace agents (Home card first; fixed one-shot tools)
     e.g. Summarize, Compare, What's missing, Next steps (checklist), Collect refs — real exec

011  Global command bar (⌘K, Gemini)
     Home + browsing: "Organize my tabs", "Create workspace for these"

012 (P1) Saved workspaces + soft suggestions
013 (P1) Desktop workspace voice (ElevenLabs)
014 (stretch) Mobile companion

MVP CUT LINE: ship 001–011. Prize extras 012–013 after that.

MINIMAL DATA MODEL
------------------
User { id, device_token_hash, created_at }
Workspace { id, user_id, name, emoji?, status: active|saved|archived, created_at }
TabRef { user_id, workspace_id|null(Other), url, title, snippet, chrome_tab_id?, last_seen }
TabEvent { time, user_id, chrome_tab_id, url, title, workspace_id, event_type }  -- hypertable
PlanItem { workspace_id, text, done, order }
Message { workspace_id, role, content }
ActionRun { workspace_id, action_id, input, output, status }
Correction { user_id, from_ws, to_ws, tab_signals }

Every durable row is user-scoped (user_id) from day one.

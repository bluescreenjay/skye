CONCISE SPEC

# AI Browser

### One-line description

**An AI-native browser that automatically turns your tabs into persistent workspaces that understand what you’re working on and can help you act on it.**

### Core Concept

Instead of treating every browser tab as an independent page, AI Browser understands that groups of tabs represent **tasks, projects, or goals**.

The browser continuously reads the user's open tabs, identifies relationships between them, and automatically organizes them into persistent **workspaces**.

**Tab → Context → Workspace → Plan → Actions**

### Core Experience

When a user opens multiple related tabs, the AI automatically creates a workspace.

For example:

```text
💻 Hackathon
   GitHub
   Figma
   MCP Documentation
   React Documentation

✈️ Switzerland Trip
   Flights
   Hotels
   Restaurants
   Google Maps

📚 Research
   Paper 1
   Paper 2
   Google Scholar

OTHER TABS
   YouTube
   Reddit
```

Organization happens continuously in the background.

Users maintain complete control and can:

* drag tabs between workspaces
* remove tabs
* create workspaces manually
* rename or merge workspaces
* move tabs into "Other"
* save/archive workspaces

The AI learns from these corrections.

---

## Workspaces

A workspace is a persistent container around a user's activity.

It contains:

* related tabs
* accumulated context
* conversation history
* an AI-generated plan
* notes
* generated content
* available actions

Closing the browser does **not** destroy the workspace.

When the user returns later, they can continue where they left off.

## Workspace AI

Every workspace has its own AI context.

Users can ask:

* "What have I found so far?"
* "Summarize everything."
* "What am I missing?"
* "What did we decide?"
* "What should I do next?"
* "Create a document from this research."
* "Update my plan."

The user does not need to repeatedly explain the context because the workspace already contains it.

---

## Contextual Actions

The AI identifies actions that would be useful for the current workspace.

Examples:

**Research**

* Summarize
* Compare sources
* Extract citations
* Create research document

**Travel**

* Compare flights
* Build itinerary
* Find restaurants
* Add events to calendar

**Shopping**

* Compare products
* Find alternatives
* Compare prices
* Create shopping list

Actions can be powered by APIs, MCP servers, integrations, or specialized agents.

The long-term goal is for the AI to **discover and recommend new actions dynamically**, rather than relying entirely on a fixed action menu.

Examples:

> "Organize my tabs."

> "Put everything related to my trip together."

> "Create a workspace for these tabs."

> "Clean up my browser."

> "Find everything related to my project."

This becomes the natural-language control layer for the browser.

---

## Mobile Companion

A mobile app provides access to the same persistent workspaces.

Users can:

* view workspaces
* ask questions
* review plans
* trigger actions
* interact through voice

The phone essentially acts as a **voice interface to the user's workspaces**.

For example:

> "What's going on with my hackathon?"

> "Summarize my research."

> "What do I still need to do?"

The browser and phone access the same workspace context.

---

## MVP

The one-week hackathon MVP should focus on the core loop:

1. Read open tabs and page content.
2. AI-cluster tabs into workspaces.
3. Display workspaces in a dedicated UI.
4. Persist workspaces across sessions.
5. Allow drag-and-drop correction.
6. Generate a contextual checklist.
7. Let users chat with each workspace.
8. Provide several real contextual actions.
9. Add a global AI command bar.

### Stretch

* mobile app
* voice interaction
* ElevenLabs voice responses
* calendar/document integrations
* dynamic action discovery

### Technical Direction

Start with a **Chrome extension + web application**, rather than building a full browser.

The extension handles tab/page access and organization.

The web application handles workspace state, AI context, plans, conversations, and actions.

A full Chromium-based browser can become the longer-term direction.

---

## Product Philosophy

Traditional browsers organize **pages**.

AI Browser organizes **work**.

> **Cursor understands your codebase. AI Browser understands your browser.**

The fundamental unit is no longer the tab.

It is the **workspace**.


THOROUGH SPEC
# AI Browser — Thorough Product Specification

## 1. Product Definition

**AI Browser is an AI-native browser experience that understands what a user is doing across their open tabs, automatically organizes related activity into persistent workspaces, and gives each workspace its own memory, plan, AI assistant, and ability to take action.**

The fundamental shift is:

**Traditional browser**

```text
Browser → Window → Tabs → Pages
```

**AI Browser**

```text
Browser → Workspaces → Tasks → Context → Actions
```

The browser should not only know **what pages are open**.

It should understand **why those pages are open**.

---

# 2. Product Thesis

People naturally use collections of browser tabs to represent larger activities.

A user might have:

* five flight tabs
* three hotel tabs
* Google Maps
* restaurant recommendations
* a Reddit discussion
* a travel guide

The browser sees fifteen pages.

The user sees:

> "I'm planning a trip."

AI Browser turns that implicit structure into an explicit workspace.

### Core thesis

> **Your tabs become workspaces. Your workspaces become agents.**

The product can be thought of as:

> **Cursor for the browser.**

Cursor understands the files, dependencies, history, and structure of a coding project.

AI Browser understands the tabs, pages, research, decisions, plans, and history surrounding a user's task.

---

# 3. Problem

Modern browsers are fundamentally page-oriented.

The browser provides mechanisms such as:

* tabs
* bookmarks
* folders
* tab groups
* browsing history

But these mechanisms require the user to manually construct structure.

A typical browsing session might look like:

```text
32 open tabs

6 research papers
4 GitHub pages
3 Google Docs
5 shopping pages
4 travel pages
2 emails
3 random articles
5 miscellaneous tabs
```

The user has to determine:

* which tabs belong together
* which tabs matter
* what the overall task is
* what they have already learned
* what remains to be done
* where to save useful information
* what external tools they should use

AI Browser automates this organization while keeping the user in control.

# 5. Tab Intelligence

The AI continuously processes information about open tabs.

Potential inputs include:

* URL
* page title
* page text
* metadata
* domain
* semantic similarity
* links between pages
* user's interaction history
* existing workspace context
* previous workspace corrections

The system uses these signals to determine whether tabs appear to belong to the same activity.

### Example

The user opens:

```text
Google Flights
United Airlines
Airbnb
Google Maps
Reddit: Switzerland travel
Zurich restaurant guide
Swiss tourism website
```

The AI creates:

```text
✈️ Switzerland Trip
7 tabs
```

The user never explicitly created the group.

---

# 6. Live Organization

Organization should be **continuous**, not a one-time cleanup operation.

The AI watches for emerging clusters.

For example:

```text
10:00 AM

💻 Hackathon
   GitHub
   Figma

📚 Research
   Paper 1
   Paper 2

OTHER
   YouTube
```

The user begins researching React agent frameworks.

The browser recognizes that the new tabs are likely related to the hackathon:

```text
💻 Hackathon
   GitHub
   Figma
   React Agents
   MCP Documentation
   Agent Framework

📚 Research
   Paper 1
   Paper 2

OTHER
   YouTube
```

The system should avoid aggressively moving tabs when confidence is low.

Possible behavior:

> "These 3 tabs seem related to your Hackathon workspace."

**[Add] [Ignore]**

This balances automation with user control.

# 7. Workspace Model

A workspace is the fundamental persistent object in the product.

A workspace contains:

```text
Workspace
├── Tabs
├── Page Context
├── AI Context
├── Conversation History
├── Plan
├── Notes
├── Generated Content
├── Actions
├── Decisions
└── History
```

Unlike a traditional tab group, a workspace survives independently of the tabs themselves.

A user can close every tab associated with a workspace while preserving the workspace.

A workspace can move through several states:

```text

   ↓
Active
   ↓
Saved
   ↓
Inactive
   ↓
Reopened
   ↓
Active
```

For example:

**Monday**

User researches an apartment.

**Tuesday**

They close everything.

**Friday**

They reopen:

> 🏠 Apartment Search

The workspace still contains:

* previously visited apartments
* research
* notes
* plan
* previous AI conversations
* decisions
* outstanding tasks

The user can say:

> "Continue where we left off."

---

# 9. User Control

AI organization should never feel irreversible.

Users can:

* drag tabs between workspaces
* remove tabs
* create workspaces manually
* rename workspaces
* merge workspaces
* split workspaces
* archive workspaces
* save workspaces
* move tabs to Other
* dismiss AI suggestions

### Learning from corrections

If the AI repeatedly places certain pages in the wrong workspace and the user moves them elsewhere, those interactions can become signals for future organization.

The system should treat user corrections as feedback rather than assuming the initial clustering is always correct.


The system can still surface suggestions when it detects meaningful relationships.

> "These four tabs may belong to a new workspace."

**[Create Workspace] [Not Now]**

This prevents the browser from forcing structure onto casual browsing.

# 15. Agent and Tool Layer

Actions can be implemented through multiple mechanisms.

Possible execution layers include:

```text
                    ACTION
                       │
          ┌────────────┼────────────┐
          ↓            ↓            ↓
         API          MCP         Agent
          │            │            │
          └────────────┼────────────┘
                       ↓
                  RESULT
```

The user should not need to know whether an action uses an API, MCP server, or agent.

For example:

> "Add these dates to my calendar."

The system identifies the calendar capability and executes it.

Or:

> "Create a research document from these papers."

The system gathers the relevant workspace context and invokes the appropriate document-generation capability.

# 27. Initial Platform Strategy

## Phase 1: Chrome Extension + Web App

The fastest implementation should avoid building an entire browser.

### Extension

Responsible for:

* reading tabs
* accessing page content
* detecting tab changes
* assigning tabs to workspaces
* moving/reorganizing tabs
* communicating with the workspace backend

### Web App

Responsible for:

* workspace UI
* AI chat
* plans
* persistent context
* actions
* generated content
* workspace history

This allows the team to demonstrate the product without needing to build browser infrastructure.

---

# 28. Long-Term Browser

If the product proves useful, the extension architecture can evolve toward an AI-native Chromium-based browser.

A full browser provides greater control over:

* tab UI
* workspace navigation
* browser state
* AI command interfaces
* page context
* agent interaction
* workspace persistence

The extension is therefore the **MVP implementation**, not necessarily the final product architecture.

# Research: Shared Domain Model

## 1. Monorepo tool

- **Decision**: pnpm workspaces (`pnpm-workspace.yaml` with `apps/*` and `packages/*`).
- **Rationale**: Constitution Principle V; fast linking of `packages/shared` into both apps; standard for TS monorepos.
- **Alternatives considered**: npm workspaces (slower, weaker linking); Turborepo/Nx (extra platform for a three-package repo — violates Principle VI); separate repos (guarantees drifting types).

## 2. Shared package shape

- **Decision**: `@ai-browser/shared` exports TypeScript types and small const enums/unions only. No runtime DB client in shared this feature.
- **Rationale**: Both Chrome (bundled) and Next.js can import types. Keeping I/O out of shared avoids pulling Node Postgres into the extension.
- **Alternatives considered**: Zod-first schemas in shared (useful later; optional, not required for 001); code-generate types from SQL (more moving parts); duplicate interfaces per app (forbidden by spec FR-011).

## 3. IDs and user scoping

- **Decision**: UUID strings (`user_id`, `workspace_id`, etc.) generated by the server later; types are `string` branded or documented as UUID. Every durable table has `user_id NOT NULL` plus FK to `users`.
- **Rationale**: Spec FR-003; multi-user later without rewrite. Device pairing token hash lives on `users`.
- **Alternatives considered**: Integer IDs (fine but UUIDs avoid collision across clients); workspace-only tenancy without `user_id` (blocks multi-user).

## 4. “Other” bucket

- **Decision**: `tab_refs.workspace_id` nullable. `NULL` means Other. No sentinel workspace row.
- **Rationale**: Spec assumption; avoids a fake workspace showing up on Home unless we filter it. Sidebar treats null workspace as Other.
- **Alternatives considered**: Sentinel `workspace` named Other (simpler queries, pollutes directory). Rejected unless a later feature proves filters are too painful.

## 5. Tab events vs tab refs

- **Decision**: `tab_refs` = current/last-known membership and snippet. `tab_events` = append-only lifecycle (opened, updated, activated, closed, reassigned). Preferred DDL: Timescale hypertable on `time`. Pivot: same columns, regular `btree (user_id, time)`.
- **Rationale**: Spec FR-006/FR-007; Tiger prize use is real (activity over time) without making the rest of the schema Timescale-specific.
- **Alternatives considered**: Only snapshots (cannot answer “yesterday”); only events (harder to render current Home list). Need both.

## 6. Chrome extension shell

- **Decision**: Vite + CRXJS, MV3, background service worker stub. No `chrome_url_overrides` newtab and no `side_panel` yet (features 005/006).
- **Rationale**: Empty shell so 002 can add ingest without inventing the repo. Side Panel / Home in this feature would violate FR-009.
- **Alternatives considered**: Plasmo (allowed pivot, similar outcome); WXT; raw webpack.

## 7. Next.js shell

- **Decision**: App Router, TypeScript, a placeholder page that is **not** product Home. No route handlers for workspaces yet (feature 003).
- **Rationale**: Constitution server host; 001 only proves the app can import `@ai-browser/shared`.
- **Alternatives considered**: Express-only API (would fight later UI reuse); empty folder without Next (weaker 001 done-when).

## 8. Env and secrets

- **Decision**: Root `.env.example` with `DATABASE_URL`, `GEMINI_API_KEY`, optional `ELEVENLABS_API_KEY`. `.env` gitignored. Comments document Tiger vs Supabase URL shapes.
- **Rationale**: FR-010; constitution secrets rule. This feature does not call Gemini or open a DB.
- **Alternatives considered**: Per-app env only (harder onboarding); Doppler/Vault (overkill).

## 9. Testing bar for 001

- **Decision**: `pnpm -r typecheck` (or root script) must pass; shared package builds; both apps import `Workspace` et al. No Jest suite required.
- **Rationale**: Constitution quality bar: integration of contracts over unit-test theater. Compile is the contract test.
- **Alternatives considered**: Full SQL migration CI against Tiger (blocked if no cloud account; optional later).

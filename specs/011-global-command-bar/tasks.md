# Tasks: Global Command Bar

**Input**: Design documents from `/specs/011-global-command-bar/`

**Prerequisites**: plan.md, spec.md, research.md, data-model.md, contracts/http.md, contracts/model.md, contracts/shared-command-types.md, contracts/extension.md, quickstart.md

**Tests**: Included, as the plan and FR-031 specify: Vitest on PGlite with an injected fake interpreter (`CommandModel`), 004's fake cluster model, and 010's fake agent model (no network, no key); a fixture of 45 phrasings; extension unit tests for the pure client, reducer, signal, duplicate, and shortcut modules on the chrome mock; one opt-in live check (`COMMAND_LIVE=1`); one manual pass on a real Chrome. They never touch Tiger and never call a real provider by default. Drop the test tasks if you want none; nothing else depends on them except the helper file (T020), which the test tasks use.

**Organization**: Grouped by user story from spec.md (US1 to US8). US1 to US4, US6, and US7 are P1; US5 (recall) and US8 (find) are P2. Order: US1 (organize and show, with the bar itself), US2 (create), US3 (agent by name), US4 (group and clean up), US7 (move, rename, merge), then US6 (never surprising: undo guards, doubt, refusals, hostile text, failures), then US5 and US8. US6 comes after the intents on purpose: its checks exercise every earlier intent. Each story's Independent Test passes with only the stories before it. The server foundation (Phase 2) includes the undo store and undo executor, because US1 and US2 both promise Undo.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: can run in parallel (different files, no dependency on an unfinished task)
- **[Story]**: US1 to US8, only inside story phases
- Paths are from the repository root.

**Rules for the implementer**
- Every model request goes through `apps/web/src/llm/` (provider choice, daily budget, concurrency limiter) via the `CommandModel` seam. Never call a vendor from command code. **Exactly one** `interpret` call per submitted command and none for empty input, `apply`, or the undo read.
- **The model never writes what the person reads.** Every sentence in a reply, preview, or result comes from `apps/web/src/command/messages.ts`, filled with values the server checked. The only model-written strings that reach state are a new workspace `name` (validated by `usableName`) and `parts` (verbatim substrings of the typed text). Never render or store other model text.
- Every SQL statement is parameterized and filters by `user_id`. Cast bare parameters in a `SELECT` or `INSERT ... SELECT` (`$1::uuid`): Postgres cannot infer their type there. Every changing action runs in one transaction that first takes `pg_advisory_xact_lock(hashtext('command:' || $1::text))` for the person.
- Never log command text, tab titles, addresses, excerpts, workspace names, model output, results, or previews. Log fixed labels and error class names only (`console.error("[command] failed", err.name)`), and never put any of them in an error body either. Stored and returned sentences are the fixed ones in `contracts/http.md` and `messages.ts`.
- **No page is ever fetched** by anything in `src/command/` (find is over saved titles, addresses, and excerpts). No 010b tool, no computer use, no multi-step planning (FR-022).
- Nothing changes without a submit; every `group`, `move`, `rename`, `merge` (and `create` that includes a person-placed tab) returns `needs_confirmation` unless the request says `confirmed: true`, decided by the **server** on the current state (research 2).
- Check real exit codes: run typecheck and tests without piping them through `tail`. Vitest hides `console.log` output of passing tests; for live checks pass `--disable-console-intercept`.
- `apps/web/AGENTS.md` warns this Next.js differs from older versions. Before T019 read `apps/web/node_modules/next/dist/docs/01-app/03-api-reference/03-file-conventions/route.md`. The new routes are ordinary JSON handlers like the existing ones; copy the shape of `apps/web/app/api/cluster/runs/route.ts` (`runtime = "nodejs"`, `OPTIONS`, CORS via `src/json.ts`, `requireUser`).
- **Extension rules.** `.ts` files outside `home/` and `sidebar/` are scanned by `apps/extension/tests/observe-only.test.ts`: no `chrome.tabs.(update|move|remove|group|...)`, no `chrome.sidePanel` (except `sidepanel-gate.ts` and, after T027, `command-shortcut.ts`), no `document.createElement` or `innerHTML =`, and only `background.ts` may call `chrome.tabs.create`. So `ui/` code (the bar, `command.ts`, `command-signal.ts`) never changes tabs; the host object (`home/command-host.ts`, `home/close-duplicates.ts`) does. Nothing in the bar keeps a history of commands, in memory beyond the current session, storage, or anywhere else (FR-030).
- **MV3 shortcut rule.** In `command-shortcut.ts`, call `chrome.sidePanel.open` **before any `await`**; Chrome accepts the shortcut as the user gesture only in the same turn.
- React StrictMode runs effects twice: guard async effects with a per-run `cancelled` flag, not a shared ref. Render every string from a reply as a React text node, never HTML.
- `next build` overwrites `.next`, which a running `next dev` uses. If a dev server is running, build from a scratch copy of the app with `next build --webpack` instead of building in place. Never `pkill` by a generic name; kill by PID.
- Never source `.env` in a shell (a parse error can print the database password); the app and scripts read it themselves. Never run anything against the Tiger database except where a task says it needs the user's approval (T069). Do not commit. Do not edit `spec.md`, `plan.md`, or `data-model.md`; if reality contradicts them, stop and say so. The plan's "Spec points to flag" (FR-020 versus User Story 2 scenario 5, the Key Entities wording, the closed-tab reading, the Side Panel choice) are already recorded; do not re-open them.
- Live checks (T066): the default provider needs the VT VPN and a personal key, with 10 concurrent requests per model, so the live test runs its requests with a small concurrency (4) and pauses between batches; with `LLM_PROVIDER=gemini` (free tier: 15 requests a minute, 500 a day, shared key) pace them under that. Never run it against a shared key without the person's say-so.

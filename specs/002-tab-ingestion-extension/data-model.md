# Data Model: Tab Ingestion Extension

This feature adds no database tables. It defines (a) the **wire records** the extension sends, derived from the canonical 001 types, and (b) the **persisted client state** the extension keeps in `chrome.storage.local`. Timestamps are UTC ISO-8601 strings. Field names follow the 001 camelCase convention.

## Wire records (defined in `packages/shared/src/ingest.ts`)

### TabSnapshotInput — one tab's current state

Derived from `TabRef` (feature 001). The extension cannot know `id`, `userId`, or `workspaceId`, so those are absent. `workspaceId` is decided by the server (constitution Principle II).

| Field | Type | From `TabRef`? | Rules |
| --- | --- | --- | --- |
| `chromeTabId` | number | yes, narrowed from `number \| null` | Live browser tab id. Valid only for the current browser session (spec, clarification Q2). |
| `url` | string | yes | `http:` or `https:` only; max ~2048 characters (truncate, never reject). |
| `title` | string | yes | May be empty. |
| `snippet` | string | yes | Plain text, whitespace collapsed, at most `SNIPPET_MAX_LENGTH` (2000) characters. Empty when unreadable. |
| `lastSeenAt` | datetime | yes | When the extension last observed this state. |
| `windowId` | number | no, ingest-only | Containing window. Not stored by 001; the server may use or ignore it. |
| `active` | boolean | no, ingest-only | True if this is the active tab in its window when the snapshot was taken. A point-in-time hint: it is not refreshed when the front tab changes. `activated` events and the request-level `active` sample are authoritative. |

### TabEventInput — one timestamped fact

Derived from `TabEvent`. `userId` comes from the device token, `tabRefId` and `workspaceId` are decided by the server (the extension leaves membership empty, meaning Other).

| Field | Type | From `TabEvent`? | Rules |
| --- | --- | --- | --- |
| `id` | UUID string | yes | Generated by the extension with `crypto.randomUUID()` when the event is captured. Stable across retries; the server counts an id once (FR-008). |
| `time` | datetime | yes | When the change happened (capture time), not send time. |
| `chromeTabId` | number | yes, narrowed | The tab the event is about. |
| `url` | string | yes | Address at event time. For `closed`, the last reported address. |
| `title` | string | yes | Title at event time. |
| `eventType` | `"opened" \| "updated" \| "activated" \| "closed"` | yes, `reassigned` excluded | `reassigned` belongs to workspace features and is never sent by this feature. |

### IngestBatchRequest / IngestBatchResponse

See `contracts/ingest-api.md`. A request carries `batchId`, `sentAt`, `fullSnapshot`, `active` (the focused window and its active tracked tab, or `null`), `tabs`, and `events`.

## Persisted client state (`chrome.storage.local`)

Nothing durable lives in worker memory. Key names are versioned with a `v1:` prefix.

### BacklogEvent — key `ev:<seq>`

| Field | Type | Rules |
| --- | --- | --- |
| `seq` | integer | Monotonic queue position, encoded in the key. Delivery order is `seq` order. |
| `event` | TabEventInput | Never contains a snippet. |
| `queuedAt` | epoch ms | Used for the 24-hour age prune. |

`meta` holds `{ head, tail }` (first undelivered seq, next seq to assign).

### DirtyTab — key `dirty:<chromeTabId>`

The latest `TabSnapshotInput` for a tab, plus a `ready` flag and `firstDirtyAt` / `lastChangeAt` (epoch ms). While `ready` is false the tab is still settling (2 seconds after its last change, or 30 seconds after its first change at the latest) and the snapshot is not delivered; once it settles it becomes ready. A normal request carries only ready snapshots; a full snapshot carries all of them so it never omits an open tab. The index key `dirty:ids` lists tab ids. At most one entry per open tab. A batch acknowledgement removes an entry only if its `lastChangeAt` is unchanged since the batch was built, so a change made while the request was in flight is kept.

### TabMirror — key `mirror`

Map of tracked `chromeTabId` to the last **reported** `{ url, title, windowId, lastSeenAt }`. It answers "did this update change anything?" and supplies the address, title, and time for `closed` events. It also defines which tabs are tracked. Tab ids are only valid within one browser session, so on browser start every mirrored tab from the previous session is closed out (a `closed` event at its `lastSeenAt`) and the mirror is cleared before the fresh full snapshot re-opens the restored tabs.

### SnippetCache — key `snip:<chromeTabId>`

`{ url, text }`: the last snippet read for a tab and the address it came from. It lets a title change on an unchanged address reuse the snippet instead of reading the page again, and is why the snippet never travels in an event. A tab is read again when the address changed, nothing is cached, or the last read found no text; pages that are still loading and discarded tabs are never read. Removed when the tab stops being tracked.

### SyncState — key `state`

| Field | Type | Rules |
| --- | --- | --- |
| `status` | `"idle" \| "ok" \| "retrying" \| "auth_failed" \| "misconfigured"` | See the transition table below. |
| `needsFullSnapshot` | boolean | Set on install or reload, browser start, any age prune or count-ceiling drop, and on 401 or 403. The sender takes the snapshot itself just before sending. Cleared when the `fullSnapshot: true` request is acknowledged, or rejected as invalid (so it cannot loop). |
| `attempt` | integer | Consecutive failed sends; drives backoff (2 s to 5 min, jittered). |
| `nextAttemptAt` | epoch ms \| null | Earliest next send. |
| `lastSuccessAt` | datetime \| null | For diagnostics. |
| `droppedForAge` | integer | Events removed by the 24-hour prune or count ceiling (the "gap note"). |
| `quarantinedInvalid` | integer | Events, and snapshot entries, the server rejected as invalid and that were removed so they cannot block the queue. |

## Rules

1. **Eligibility (FR-013)**: a tab is reportable only if its window is not incognito and its URL scheme is `http:` or `https:`. Everything else is never read, queued, or sent.
2. **Snippet (FR-004/005)**: ≤ 2000 characters of plain text; on any failure the snippet is `""` and the tab is still reported.
3. **Ordering (FR-007)**: events are delivered strictly in `seq` order; batches take a contiguous `head..head+99` range and are deleted only after a 200.
4. **Retention (FR-007, Q3)**: keep at least the last 24 hours. Older events may be dropped oldest-first; each drop increments `droppedForAge` and sets `needsFullSnapshot`. A ceiling of 20,000 events (FR-007) caps the backlog on the same path.
5. **Identity (FR-008/017)**: the extension never decides that two tabs are the same. It sends `chromeTabId` plus address and title; the server matches and de-duplicates.
6. **Size**: ≤ 100 events per request; snapshots ≤ open-tab count. Total stored data must stay far under the 10 MB `storage.local` quota.

## State transitions

### Tab tracking (per browser tab)

| From | Trigger | To | Emits |
| --- | --- | --- | --- |
| Untracked | created or updated with an eligible URL | Tracked | `opened` (immediate if created with an eligible URL, otherwise at the settle flush) |
| Tracked | title/URL/status change, settled (~2 s, capped at 30 s) and net change vs `mirror` | Tracked | `updated` |
| Tracked | activated, or its window gains focus | Tracked | `activated` (immediate) |
| Tracked | navigates to an ineligible URL | Untracked | `closed`, without the ineligible URL |
| Tracked | tab removed | Untracked | `closed` (immediate) |
| Tracked | moved to another window | Tracked | nothing (window id refreshed on the next snapshot) |
| Tracked | replaced by another tab id | Tracked (new id) | `closed` (old id) now; `opened` (new id) once it settles. The new id is one the backend has never seen, so claiming "same tab" would be the extension deciding identity (FR-017) |

### Sync status

| From | Trigger | To |
| --- | --- | --- |
| any | config missing at startup | `misconfigured` |
| `idle` / `ok` / `retrying` | send acknowledged (200) | `ok` (attempt reset) |
| `idle` / `ok` | network error, timeout, 408, 429, 5xx, or any other unlisted status such as 404 | `retrying` (`nextAttemptAt` set; nothing is sent before it) |
| `retrying` | further failure | `retrying` (attempt + 1, longer delay: 2 s doubling to 5 min, up to 20% jitter, or `Retry-After`) |
| any sending state | 401 or 403 | `auth_failed` (stop sending; keep backlog; `needsFullSnapshot` set) |
| `auth_failed` | extension reloaded or browser restarted (`resetSyncState`) | `idle`, with a full snapshot requested and the wait cleared; the next send moves it to `ok` |
| `retrying` | extension reloaded or browser restarted | `idle`, wait cleared |
| `misconfigured` | (needs a rebuild with valid config) | unchanged until reload |

## Mapping to feature 001 and the future server

| Wire field | Becomes on the server (feature 003) |
| --- | --- |
| snapshot `url`/`title`/`snippet`/`lastSeenAt`/`chromeTabId` | `TabRef` upserted by user and address; `chromeTabId` refreshed from each snapshot; tabs missing from a `fullSnapshot: true` request lose their `chromeTabId` (no longer live) |
| snapshot `windowId`/`active`, batch `active` | Transient; used to answer "which tab is active" for the Sidebar |
| event fields | `TabEvent` row (`user_id` from the token, `tab_ref_id` resolved by the server, `workspace_id` null = Other) |
